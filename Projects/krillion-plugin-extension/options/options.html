Krillion · settings

Questions are read from the game you are playing and sent to the AI endpoint you choose below. Nothing else is sent.

Show

With every answer you submit, the game receives how it was entered: keystroke count and timing, and counters for pastes and synthetic input (seen in its websocket traffic). Pasting a copied suggestion registers as a paste. This is your call; turn the switch off and the rows become read-only, so you type answers yourself.

Only the first daily question that appears gets a request, and that request is a single call with no follow-ups for missing answers (it asks for 2 extra to make up for that). The other six wait until you reload, or until you press ↻ or "+ more" on them. A list the extension already remembers is shown without any request. Party rounds are not affected.

AI endpoint (any OpenAI-compatible API)

The key is stored unencrypted in this browser profile and only the extension's background worker uses it. The page never sees it. Saving asks Chrome to allow this extension to contact the endpoint's host.

Your leanings

The extension records the answers the game accepted from you (daily dive, and party rounds where it can tell which player you are) and flags the ones the AI never suggested. Those are sent to the AI as examples of what you know that it misses, with an instruction to follow the same leanings when the prompt allows: if your own answers lean East Asian, it tries East Asian answers where the question fits, mixed with the usual ones. It never overrides the question's constraints. Needs "Learn from game results" below to be on.

Your recent answers and this text are sent to the AI endpoint you configured above, along with each question.

Learning & data

The game reports every answer in a party round: accepted ones with their real rarity, rejected ones with a reason. The extension compares that with the tier the AI predicted and tells the AI where its labels are off, what the game rejected before on the same prompt, and whether rejected answers run longer than accepted ones. It cannot retrain the model; it measures and corrects in the prompt. Answers and rarity only, stored on this computer, kept across sessions.

When a party game ends (a win, or the room going back to the lobby), or you finish the daily dive, the extension builds a summary: what the game accepted and rejected per category, how your suggestions fared, accepted answers the AI never suggested (its blind spots), and your own results. The summary is always saved and boiled down to short conclusions that go into later requests. With this switch on it is also sent to your AI endpoint in one extra request per game, and the lessons the model writes are kept and used the same way. Only answers the game accepted, the AI's own suggestions and your own answers are listed; other players' typing is counted, never quoted.

Keeps every party event per game (answers, rarity, pops, wins) so you can export it as JSON or CSV from the toolbar popup's Learning tab. Players are stored as salted hashes; names and chat are never stored. Turning either switch off stops the extension reading those events.

A full, unfiltered recording of the party websocket for analysis: every frame in both directions, byte for byte, plus connection open/close events. It includes player names, chat and what everyone is typing, because that is what the game sends. Stored only on this computer; the connection URL is saved without its query string (player key and guest token), and any field named key/token is replaced by "[redacted]". Export as JSON Lines from the toolbar popup's Learning tab. Up to about 200 MB are kept; the oldest recordings are dropped first.

Session memory

For 12 hours the extension remembers, per question, every suggestion it showed and your ✓ / ✗ marks. It uses that to avoid repeating answers, to tell the AI what the game accepted or rejected (for this question and recent ones), and to restore a list after a page reload without another API call. Stored only in this browser profile.

System prompt

Controls how the AI answers. The default asks for a JSON object, {"answers":[{"answer":"…","tier":"…"}]}, and the extension also turns on the API's JSON mode. Keep that shape or the window can't read the reply or colour the tiers. {count} becomes the number above, and {example} becomes a sample reply with exactly that many answers (models copy the length of the example).
